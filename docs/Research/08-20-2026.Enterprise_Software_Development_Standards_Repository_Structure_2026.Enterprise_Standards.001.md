## Research Summary: Enterprise Software Development Standards and Repository Structure (2026)

**Source**: Multiple sources including repository standards frameworks, OSS specifications, and enterprise playbooks (2024-2026)  
**Date**: 2026-08-20  
**Research Category**: Enterprise Standards  
**Focus**: Modern expectations for enterprise software repository structure, documentation, and quality practices  

### Key Findings

#### The Shift to AI-Native Repositories
Modern enterprise repositories are evolving to be "AI-native" - designed for effective collaboration between humans and AI coding agents. Key characteristics include:

1. **Explicit Context Layer**: Rather than relying on implicit team knowledge, repositories now include explicit AI guidance files
2. **Structured Communication**: Clear separation between human-facing documentation and AI-operating instructions
3. **Versioned Guardrails**: Deterministic boundaries for AI behavior rather than ad-hoc prompts
4. **Context Layering**: Different levels of context (project-wide, module-specific, task-specific)

#### Core Repository Structure Standards

Based on analysis of multiple frameworks (Repo Standards, OSS_SPEC, Agent-Ready Template, AEEF Standards, etc.), enterprise repositories in 2026 should include:

##### **Root Level Essentials**
```
<repository>/
├── README.md                 # Project overview (human-first)
├── AGENTS.md                 # Canonical AI agent guidance (single source of truth)
├── LICENSE                   # SPDX-identified license
├── CONTRIBUTING.md           # How to contribute
├── CODE_OF_CONDUCT.md        # Community standards
├── SECURITY.md               # Vulnerability reporting
├── CHANGELOG.md              # Release notes
├── .gitignore                # Language-appropriate ignores
├── .editorconfig             # Cross-editor formatting baseline
```

##### **Documentation Hierarchy**
```
docs/

├── architecture.md           # Module layout and design decisions
├── specs/                    # Functional specifications and requirements
│   └── spec.md               # Main specification file
├── adrs/                     # Architecture Decision Records (MADR format)
│   └── 0001-*.md             # One ADR per file

├── runbooks/                 # Operational procedures
├── guides/                   # User and developer guides
```

##### **AI-Specific Infrastructure**

#### Critical Standards and Practices

##### 1. **AGENTS.md as Single Source of Truth**
- **Must** be the canonical file for AI agent guidance
- Tool-specific files (CLAUDE.md, .github/copilot-instructions.md, .cursorrules, etc.) must be **symlinks** to AGENTS.md
- Should cover:
  - Build and test commands (Makefile or script targets)
  - Commit and PR conventions (conventional commits, PR title format)
  - Where new code goes (routing table for change types)
  - Documentation sync points (what to update when X changes)
  - Website staleness policy (when to regenerate site)

##### 2. **Documentation-First Development**
- Every change to a running system follows a specific cascade:
  - Spec/ADR → Implementation → Tests → Deployment/Multi
  - Downstream artifacts never change without upstream changes first
  - Ensures AI can derive implementation from specification

##### 3. **Architecture Decision Records (ADRs)**
- Lightweight, decision-focused documentation
- Format: MADR (Markdown Any Decision Record)
- Each file: one decision with status (proposed/accepted/superseded), context, alternatives, consequences
- Stored in `docs/adrs/` as `0001-description.md`, `0002-description.md`, etc.
- Superseded decisions marked with `status: superseded by ADR-NNNN`

##### 4. **Conventional Commits as Communication Standard**
- Commit messages trigger specific artifact updates:
  - `feat:` → New feature implementation
  - `fix:` → Bug fix
  - `spec:` → Spec change → Requires ADR update
  - `arch:` → Architecture change → Requires ADR and possibly spec update
  - `refactor:` → Code restructuring (no behavior change)
  - `test:` → Test additions or modifications
  - `docs:` → Documentation only
  - `chore:` → Maintenance work (deps, tooling, build)

##### 5. **Quality Gates and Checks**
- Pre-commit/pre-merge/pre-deploy checks enforced via:
  - Tool-specific hooks (e.g., `.claude/hooks/*.sh` for ForgeCraft)
  - Manual validation checklists
  - CI/CD pipeline gates
- Key check areas:
  - Spec/ADR alignment
  - Spec/code alignment
  - Spec/harness (test) alignment
  - Documentation completeness

##### 6. **Three-Layer Recording System**
Modern enterprise repos distinguish three layers of record:
1. **Project Layer**: Repo-controlled (docs/, .forgecraft/, .claude/hooks/) - Specs, ADRs, decisions, schemas
2. **Individual Layer**: Local AI memory (Chronicle: `~/.chronicle/chronicle.db`) - Personal session notes, debugging context
3. **Team Layer**: Shared memory (Chronicle Team: cloud Postgres) - Cross-developer patterns, team insights

#### AI-Specific Practices for Enterprise Development

##### **Prompt Engineering Standards**
- Move from temporary prompting to permanent structure
- Use repository-scoped AI context files (e.g., `src/auth/CLAUDE.md`)
- Module-scoped context prevents agents from applying wrong conventions (e.g., API patterns to persistence code)
- Each module CLAUDE.md should include:
  - Module purpose and boundaries
  - Module-specific naming conventions
  - Key dependencies and usage patterns
  - Testing expectations (unit vs integration)
  - Files the agent should never modify (generated code, migrations)

##### **AI Agent Operating Procedures**
- Define > Standardize > Harden > Verify workflow pattern
- Reusable skills stored as SKILL.md files in skills/ directories
- Clear delineation of agent responsibilities by business function
- Versioned guardrails that evolve with the codebase

##### **Context Management for Long-Horizon Tasks**
- Structured note-taking (e.g., NOTES.md or AGENT.md files)
- Compaction strategies for context window management
- Sub-agent architectures for complex tasks (specialized agents + synthesizing lead agent)
- Regular context pruning based on predicted relevance for next steps

#### Implementation Guidelines for Enterprise Teams

##### **Migration Path for Existing Repositories**
1. **Inspect current structure** - Identify gaps against target standard
2. **Generate AGENTS.md** - Consolidate AI guidance into single source of truth
3. **Create .agents/context-index.md** - Repository map for AI navigation
4. **Add local AGENT.md files** - Near complex/modules with sharp edges
5. **Define workflows and guardrails** - Standardize AI agent behavior
6. **Validate ANR compliance** - Ensure structure supports effective AI collaboration
7. **Choose/apply stack profile** - Add technology-specific guidance if needed
8. **Start implementing domain** - Begin feature work in src/

##### **Validation Checklist for AI-Native Repositories**
- [ ] Single source of truth for AI guidance (AGENTS.md with symlinks)
- [ ] Clear repository map (.agents/context-index.md)
- [ ] Module-scoped AI context where needed (src/*/CLAUDE.md)
- [ ] Reusable AI skills (.agents/skills/*.md)
- [ ] Defined workflows (.agents/workflows/*.md)
- [ ] Versioned guardrails (.agents/guardrails/*.md)
- [ ] Documentation follows doc-first cascade principle
- [ ] ADRs maintained for significant architectural decisions
- [ ] Conventional commits used for communication
- [ ] Quality gates enforced at appropriate stages
- [ ] Three-layer recording principle understood and supported

#### Emerging Trends in Enterprise Repository Standards (Late 2026)

1. **AI-First Design**: Repositories being designed primarily for AI agent usability, with human consumption secondary
2. **Dynamic Context Generation**: Systems that automatically generate relevant context slices for specific tasks
3. **AI-to-AI Communication Standards**: Protocols for agent collaboration within repositories
4. **Continuous Conformance Checking**: Real-time validation of repository standards adherence
5. **Standardized Agent Interfaces**: Common formats for agent skills, workflows, and guardrails across organizations

#### Conclusion

Enterprise software development in 2026 emphasizes creating repositories that are effective collaboration environments for both humans and AI agents. The key principles include:

1. **Explicit over Implicit**: Replace tribal knowledge with documented standards
2. **Structure over Ad-hoc**: Permanent repository structure replaces temporary prompting
3. **Clarity over Cleverness**: Optimize for the next reader (human or AI)
4. **Separation of Concerns**: Clear boundaries between different types of content and responsibilities
5. **Continuous Improvement**: Standards that evolve with technology and practice

These standards aim to reduce friction, increase maintainability, and enable scalable, high-quality software development in increasingly AI-augmented environments.
